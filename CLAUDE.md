# CLAUDE.md: Personal Planner

Single-user, desktop-first planner (see `docs/plan.md` for the original feature list, `README.md` for deployment).
Guiding rule: **use existing libraries and write as little code as possible.**

## Tooling (important)

- NixOS with flakes, no global node. Run everything via `nix develop -c <cmd>`. The flake only sees **git-tracked** files.
- **bun** everywhere: package manager, `bunx`, dev/prod runtime, tests (`bun test`, files in `tests/`). Never use npm/pnpm/npx/vitest.
- `bun run dev` = `bun --bun vite dev` (the Bun runtime is required for `bun:sqlite`). `bun run build`, then `bun ./build`. `MODULES=calendar,tasks bun run build` builds without the other modules (see **Modules**).
- Checks: `bun run check` (svelte-check), `bun test`, `bun run build`.
- All deps are **devDependencies** on purpose: adapter-bun bundles devDeps into `build/`, so the Docker runtime image needs no `node_modules`.
- `postinstall` copies Excalidraw fonts to `static/fonts` (gitignored) so they're self-hosted (`window.EXCALIDRAW_ASSET_PATH = '/'`).

## Stack / versions (Nov 2026)

SvelteKit **3** (config lives in `vite.config.ts`; no `svelte.config.js`; `#lib/...` subpath imports instead of `$lib`; use `Response.json()` not `json()`; `$app/state`), Svelte 5 runes, Vite 8, TS 6, Tailwind 4, shadcn-svelte (generated components in `src/lib/components/ui`, don't hand-edit), FullCalendar **v7** (`fullcalendar` package, `fullcalendar/*` plugins, forma theme), CodeMirror 6 + lezer-markdown (own live-preview markdown editor), Excalidraw 0.18 (React, mounted in Svelte), pdfjs-dist, typst.ts (WASM) + ts-fsrs (flashcards), lucide (vanilla, for the project icon set), ical.js, tsdav, timezones-ical-library (VTIMEZONEs), rrule, tinykeys, date-fns, layerchart (shadcn chart).

## UI style

Strictly **monochrome and minimal**, after the "Planner UI Redesign" design canvas (claude.ai artifact T8FjZAVw1my97zokgeKv28; its grey palette is the token set in `layout.css`, plus `--panel`, `--ev` (event fill), `--line2` (control borders), `shadow-panel`). Color appears only as small category/project markers (dots on grey event blocks, rings for feeds, squares for tasks, flags for deadlines) and, muted, in the syntax highlighting of code blocks in notes (user's call; `hue()` in `editor/theme.ts`). FullCalendar (`--fc-forma-*`) variables are mapped to shadcn tokens in `src/routes/layout.css`; the markdown editor's theme is `src/lib/editor/theme.ts`.

**No native pickers/dialogs**: use `AppSelect` (shadcn Select, `''` = none), `ColorPicker` (swatch popover), `DateInput` (calendar popover + 24h TimeField, saves on blur), `choose()/confirmAction()/ask()` from `src/lib/choice.svelte.ts` (rendered by `ChoiceDialog`). Only the OS file chooser remains.

## Architecture

- **SPA**: `ssr = false` in `src/routes/+layout.ts`. The server only serves JSON + files.
- **Storage** (`src/lib/server/db.ts`): SQLite document store via `bun:sqlite`: table `docs(coll, id, data JSON)`, no ORM and no migrations (all fields optional). FTS5 table `fts` is kept in sync per write by `indexers[coll]`. Search snippets are HTML-escaped server-side (they're rendered with `{@html}`).
- Collections: `projects, folders, notes, tasks, events, categories, feeds, feed_event (read-only, generated), pomodoros, settings (single doc id "settings"), files (meta; blobs in DATA_DIR/files/<id>), cards, mail_accounts`. Files with `tree: true` are items of the notes tree; `cards` are flashcards whose `deckId` is a note with `type: 'deck'`. Types are in `src/lib/types.ts`.
- **Events and tasks are RFC 5545 objects** (user's call, so other calendar apps work on them): `src/lib/server/ical.ts` converts `CalEvent` ⇄ VEVENT and `Task` ⇄ VTODO with ical.js (mapping table in `MIGRATIONS.md`; planner-only fields are `X-PLANNER-*`; writing patches our properties into the previous text, so foreign properties survive). `src/lib/server/dav.ts` keeps table `dav` (one row per calendar object resource: ics text, href, etag, dirty, deleted): the ics is the truth, the `events`/`tasks` docs are its projection (the client and `types.ts` didn't change). The API routes call `changed(coll, id)` after a write (`rebuild()` → rows dirty → debounced `push()`); `pull()` (ctag, then etag listing + multiget) writes docs with `put` directly via `project()`. `sync()` runs at startup, every 5 min, and on `POST /api/dav` (client: tab focus, every 5 min, "Sync now"; `changed: true` makes it reload events + tasks). Env: `CALDAV_URL` (one collection), `CALDAV_USER/PASSWORD`, `CALDAV_TASKS_URL`; without them only the table is kept. Docs from before are converted by `migrate()` in `init`.
  - One doc ≠ one resource: `times[n]` is the resource `<id>_t<n>` (RELATED-TO the event; renumbered when one goes), and a RECURRENCE-ID override made elsewhere is a doc `<uid>_r<recurrence-id>` living in the series' resource (plus an exdate on the series doc, which is _not_ written as EXDATE while the override exists). `owner()`/`partOf()` map ids to resources.
  - Timed values are written in UTC, those of recurring items with `TZID=<TZ>` + VTIMEZONE (from `timezones-ical-library`), so DST matches our wall-clock recurrence. `DUE` can't stand beside `DURATION` and has the type of `DTSTART` (hence `X-PLANNER-END`, and a deadline as 23:59:59 beside a timed start).
  - A failed PROPFIND/REPORT must throw (`props()`): tsdav returns failures as responses without `props`, and an "empty" listing would read as "everything was deleted there". A changed `CALDAV_URL` resets all hrefs for the same reason.
  - 412/404 on push: the remote text becomes `prev` and our fields go on top (planner wins per field we know).
- **Generic API**: `GET/POST /api/[coll]`, `GET/PATCH/DELETE /api/[coll]/[id]` (PATCH = JSON merge patch, `null` deletes; DELETE returns the deleted doc). Extra: `/api/search`, `/api/feeds/sync`, `/api/upload`, `/files/[id]`, `/api/backup`.
- **Client data layer** (`src/lib/data.svelte.ts`): every collection is loaded at startup into `db.<coll>.items` (notes without `content`/`scene`). `create/update/remove` are optimistic and record before/after snapshots → global `undo()/redo()`; `batch()` groups ops into one undo step. Pass `record=false` for autosave-style writes (note bodies, canvas scenes, settings).
- **Global UI state** (`src/lib/ui.svelte.ts`): focused project (`inFocus()` filters every view), focus mode, palette/pick mode, open task/event editor, `draft` (unsaved new event).
- **Floating panels** (`FloatingPanel.svelte`): event, task and feed-event panels float without a scrim, docked to a window corner; the grab handle on top moves them and they snap to the nearest corner (`localStorage['panel:<key>']`); Escape closes. `EventEditor`/`TaskEditor` show details first, "Edit" or `e` switches to the editor (`editingId`); a draft is always the editor. One panel at a time (clicks clear the others). `choose()` dialogs: the last option is the primary (ink) button.
- **Settings** are a `FloatingPanel` (key `settings`, 860px, `overlayHandle`) with vertical tabs, mounted in `(app)/+layout.svelte`: `ui.settings` = open tab, `openSettings(tab)` (sidebar, `g ,`, palette; `/settings#<tab>` just opens it over the home page). Tabs: General and Categories (core, `components/settings/`), the rest come from the modules' `settingsTabs` (Calendars, Mail, Pomodoro, Flashcards, Templates); feeds and mail accounts are `Row`s that open one at a time, fields in `Field` (shared classes in `settings/styles.ts`). A warning icon on a tab = a feed/CalDAV/account sync error.
- **Calendar** (`src/modules/calendar/Calendar.svelte`): FC's toolbar is off: the component draws its own header (title, week number, Today, Daily note, Tasks toggle, Day/Week/Month) and takes the tasks pane (the tasks module's `calendarAside`, `src/modules/tasks/CalendarPane.svelte`) as the `aside` snippet; other modules add entries through `calendarSources` (mail: `src/modules/mail/calendar.ts`). Entries are drawn by `entryContent` (HTML) and tagged by `entryClass` (`ev ev-<kind>`, `ev-nc` = no colour); `layout.css` `.ev` rules override forma's tint and stripe with `!important`, the mark uses `var(--fc-event-color)`. own events + tasks come from one `local` event source and recurring events are expanded **by us** (`occurrences()` in `src/lib/tasks.ts`). Feed events come from `/api/feed_event?start&end`. Event-source functions must return a Promise (FC ignores plain arrays). Drag-select only creates `ui.draft` (entry class `ev-draft`); `EventEditor` stores it on "Create"/Enter, closing asks "Discard new event?". Existing events save field by field.
  - `CalEvent.times` are further times of one event, each with its own start/end/rrule (`allDay` and `exdates` are shared). `eventToFc()` gives them entries with `extendedProps.time` (index), which `ui.event.time` and `moveEvent()` carry along, so drags and "only this one" act on that time. An event with `times` can't be dragged between all-day and timed.
  - FC v7 class names are **hashed**: style/query via roles and data attributes (`[role=cell][data-date]`, `[role=heading][id$=":title"]`) or FC's `*Class` options.
  - Month view = custom `month` view (`multiMonth`, 12 stacked months); scrolling near either end calls `prev()/next()` and restores the anchor month's position (endless scroll); the header title follows the top month (`monthTitle()`). The top strip of a day cell opens the day view (window-capture listener, so FC doesn't start a selection).
  - Tasks: done/cancelled are hidden; the "Tasks" toolbar toggle (`localStorage.calTasks`) hides all (the tasks pane beside the calendar, due sections + Unscheduled, has its own key `calPane`); all-day rows are capped (`dayMaxEventRows`/`dayMaxEvents` → "+N more"). A task gives a block (`task:<id>`, if it has a start) and a flag marker on its deadline (`deadline:<id>`): `taskToEvents`. `taskEntries()` picks per view: month = only the markers; week/day = timed tasks are **background events** (muted `.task-bg`, never narrow events), overlapping ones in columns of their own (`columns()` in `tasks.ts` → classes `tc-n<N> tc-i<I>`, CSS with `!important` since FC pins fills). It goes by `viewType`, which `datesSet` keeps (and refetches): FC fetches for a new view while `cal.view` is still the old one. FC's event layer covers the column, so clicks on them are hit-tested in `onCapture` via `elementsFromPoint` (an event on top wins); they can't be dragged there (reschedule in the task editor).
- **External feeds** (`src/modules/calendar/server/feeds.ts`): ICS via fetch, CalDAV via tsdav; expanded with ical.js (−90d…+365d) into `feed_event`. Hourly sync in the calendar module's `module.server.ts` `init`, nightly backup in `hooks.server.ts` `init`. A sync replaces the feed's events, except with `Feed.keepPast`: then events that ended before the window stay. `STATUS:TENTATIVE` → `tentative` (like `CalEvent.tentative`: class `tentative`, striped). Per-feed `show` (`all` default = only when no project is focused, `always`, `projects` + `projectIds`): `feedVisible()` in `tasks.ts`, used by the calendar and the palette.
- **Mail** (plan and milestone notes in `docs/email.md`; M0–M5 done: reading, triage, writing, turning into items, invitations): accounts are docs of `mail_accounts` (passwords stripped from every API response by `pub()` in `db.ts`, also for `feeds`). Messages are **not** docs: `src/modules/mail/server/mailstore.ts` keeps a cache in a second SQLite file `DATA_DIR/mail.db` (`msg` rows per account/folder role/UID, `folder_state` with UIDVALIDITY/UIDNEXT/MODSEQ, FTS5 `mail_fts`) plus raw `mail/<account>/<sha1(Message-ID)>.eml`; the IMAP server is the truth and the cache can be deleted. `src/modules/mail/server/mail.ts` syncs with imapflow (new UIDs newest first in chunks, flags via CONDSTORE `changedSince`, removals by comparing UIDs when the count differs, UIDVALIDITY change → folder read again; complete messages for 90 days, a 2 KB partial text part for older snippets), one run per account at a time (`running`), and parses `.eml` with postal-mime for the reading pane. Thread id = hash of the first References id, else In-Reply-To, else Message-ID. Sync runs at startup and every 5 min (`hooks.server.ts`); `POST /api/mail/sync` only starts it (202): progress goes out as server-sent events (`GET /api/mail/events`, `onMail()`), which `startMail()` in `src/modules/mail/mail.svelte.ts` listens to for the whole app (counts, `mail.version` → the mail page reloads its list). Page `(app)/mail/[[account]]` (view and open thread in `?view=&m=`), components in `src/modules/mail/components/`. HTML mail goes in an `<iframe sandbox="allow-same-origin allow-popups…" srcdoc>` with a CSP meta (remote content only after "Show images"); attachments come from `/api/mail/part/<msg>/<n>` with `CSP: sandbox`. HTML that is text in fact comes with `simple: true` and `text` = its conversion (`htmlText()`, `html-to-text`) and is read in the text view (dates, quote bars), "Show original" brings the frame. The conversion for reading is markdown (`htmlText(h, true)` → `md: true`: `**bold**`, `_italic_`, `[text](url)`, `#` headings, written as private-use marks first so that the mail's own `*`, `_`, `](`, `#` can be escaped; snippets and search keep the plain form). `mailBlocks()`/`mailInline()` in `src/modules/mail/mail.ts` turn a text into what `MailBody` draws: lists (also in plain-text mail), tables, quotes, and inline markup **only** for `md` text, so `_this_` typed in a plain mail stays as typed. Reply quotes and notes get the markdown as is. `classify()` decides on the DOM (htmlparser2): tracking pixels and icons (≤ 48px) don't count, up to 3 other pictures are left out (`pictures` → "N pictures not shown"; cid ones are listed as attachments), tables must be tables of data (`dataTable()`: a row with two filled cells, short cells, nothing nested), which `htmlText()` writes as markdown tables and `MailBody` draws as tables (also in plain-text mail); forms, media, backgrounds and layout tables stay in the frame. Port 143 = STARTTLS, other ports TLS. Triage: `act()` changes the cache and queues `ops` (pushed at once and before every sync, one queue per account: `serial()`); archive moves rows with a negative placeholder UID until MOVE's UID map or a sync settles it (`\All` archives: drop the inbox row / COPY back). Later and manual project are `mail_threads` docs (undoable); `threadProject()`/`mailVisible()` in `src/modules/mail/mail.ts` decide project and focus on both sides (the server filters list, counts and palette hits by `?project=`). Later threads are passed into the SQL as JSON; passed ones sort by their later time. Calendar: `mailEntries()` (`.ev-mail` blocks), `ui.slotFor` turns the next drag-select into a later time. `watch()` keeps an IDLE connection per account (on `globalThis`, `autoIdleDelay: 1000`), whose events start a sync; new unread inbox mail goes out as `fresh` in the event and the browser notifies. Writing: `mail_drafts` docs (autosaved, `quote` = the quoted original, `quick` = quick-reply draft); `replyDraft()` in `src/modules/mail/mail.ts`; `Compose.svelte` (FloatingPanel `mail`, mounted in `(app)/+layout.svelte`, `ui.compose`), `QuickReply.svelte`, `RecipientField.svelte` (`/api/mail/contacts`). The compose panel can fill the window (`FloatingPanel` `full`, `localStorage.composeFull`, Ctrl Shift F); a `bindKeys` Escape is skipped while the focus is in a `[role=dialog]`, so it closes the panel and not the page's thing. `send()` builds the message once with nodemailer (`compose()`: marked HTML, `/files/<id>` pictures as cid, files, forwarded attachments), SMTP (465 TLS, else STARTTLS), APPEND to Sent unless Gmail; failures queue the draft, `afterSync()` resends and clears `MailThread.waiting` when someone answered. A message joins the thread of a known message it refers to (`threadOfMsgid`). Turn into: `toTask()` (panel `MailToTask.svelte`, `turn.task`), `toEvent()` (`ui.draft` + `mail`), `toNote()`; `MailLink` on tasks/events/notes (`X-PLANNER-MAIL` in `ical.ts`), the reading pane finds them by `mail.thread` (`itemsOf()`), `MailChip.svelte` shows the link on the items. Dates: `src/modules/mail/dates.ts` (chrono-node en + de), underlined in `MailBody`. `POST /api/mail/part/[msg]/[n]/save` puts an attachment into the notes tree. Invitations: `handleInvites()` (in `afterSync`) → `importEvent()` in `dav.ts` (the organizer's VEVENT text as the resource, METHOD removed, our fields written on top; `invite` = `X-PLANNER-INVITE`), table `invites` in `mail.db` remembers handled UIDs/SEQUENCEs; `answerInvite()` sets PARTSTAT (`setPartstat()`) and sends the REPLY as a draft with `ical`; `InviteCard.svelte`.

## Decisions / assumptions (agreed with user)

- WebDAV storage was **dropped** (user's call). Local volume `/data` only.
- Reminders: **browser only** (Notification API + toast while a tab is open; missed reminders <24 h fire on open; suppressed during focus mode).
- Note modes: **convert type** (md ↔ canvas; canvas→md keeps only text, so it asks to confirm first).
- PDF in canvas: **pages as images** (drawable over), grouped as one object with layout settings.
- A feed limited to projects still shows in "All projects".
- Inbox = open top-level task with none of start/end/deadline/priority/status/reminders (`isInbox` in `src/lib/tasks.ts`).
- Focus mode = hide sidebars + fullscreen + mute reminders. A faint "x" in the top right corner leaves it (iPad: no keyboard, maybe no fullscreen).
- Recurring edits: drag asks "only this one / all"; "this" = EXDATE on the series + standalone copy. Editor fields edit the whole series; "Edit only this occurrence" detaches.
- Auth: none in-app; Authelia via NPM forward-auth. `REQUIRE_AUTH_HEADER=true` enforces the `Remote-User` header.

## Gotchas

- Recurrence math is DST-safe via "floating" wall-clock times (`toFloat/fromFloat` in `tasks.ts`); EXDATEs are stored as local ISO (`localIso`).
- `e.currentTarget` is null after an `await` in event handlers, so capture it first.
- Excalidraw elements can't go through `structuredClone`; JSON-clone them.
- Never pass `color: undefined` to FullCalendar: it becomes the string `"undefined"` → transparent event fill. Omit the key (`...(color && { color })`). Don't use `opacity` on events either (grid lines show through).
- shadcn sheets and alert dialogs are both `z-50`; `layout.css` lifts alert dialogs to 60 so confirms opened from a sheet are on top.
- A dialog closed on Enter must `preventDefault()` the keydown, or the same Enter re-activates the trigger button that gets focus back.
- bits-ui menus return focus to their trigger on close; use `onCloseAutoFocus={(e) => e.preventDefault()}` when the action focuses something else (inline rename).
- `bunx shadcn-svelte add` wants to overwrite `button`; back it up / restore it, then run prettier on the new component dir.
- Text laid out by `convertToExcalidrawElements` before Excalidraw's fonts load is mis-measured, so converted notes use fontFamily 2 (system sans) and scenes go through `restoreElements(..., { refreshDimensions: true })` on load.
- Don't `pkill -f` with a pattern contained in your own command line (it kills the shell).
- tinykeys v4 ignores keys from inputs/contenteditable by default; `bindKeys` overrides that `ignore` and filters with its own `typing()` so the `always` shortcuts (Ctrl+K, Ctrl+L) work inside editors.
- CodeMirror tests run headless in `bun test` as long as they only build an `EditorState` (no `EditorView`). In Playwright, redo is `Control+Shift+Z` (capital Z) and Ctrl+click needs `keyboard.down('Control')` around `mouse.click`.
- Markdown editor lists (`editor/lists.ts`, `ListItem` in `preview.ts`): every line of a list item gets `--md-depth` and its indentation/marker is wrapped in an inline-block `.md-lead` (min-width = the indent, negative margin, right-aligned), which gives the hanging indent without measuring text. A replace decoration starting where a mark starts ends up **outside** the mark unless the mark is `inclusiveStart`. Widgets must return `false` from `ignoreEvent()` for the plugin's `eventHandlers` to see their clicks. A `ListItem`/list node may start before its `ListMark` (in the indentation): use the mark's position. Sizes shared between lines (the list indent) are in `rem`: code and fence lines have their own font size, so `em` differs per line.
- Markdown editor layout and files: the space beside the text is padding of `.cm-scroller`, not of `.cm-content` (`drawSelection` draws full-line selections as wide as the content's border box); the `margin` plugin in `editor/index.ts` makes clicks there land in the line. A marker without its space yet (`-`) gets `.md-lead-bare` (CSS appends the space) so it doesn't move when the space is typed. Right-click on a link/picture of an uploaded file (`fileAt()`) offers rename/download/delete (not in embeds: no `db`, no dialogs). `moveItem` (Ctrl+Shift+↑/↓) swaps whole line blocks of sibling items and leaves the markers in place.
- Markdown editor tables (`editor/tables.ts`): rows stay document lines with `display: table-row` and cells are marks with `display: table-cell` (the delimiter row is `display: none`), so the browser sizes the columns and cells are edited as ordinary text. Pipes and padding are hidden; `stayInCells` (transaction filter) keeps the cursor out of them and `keepPipes` (change filter) keeps user edits from deleting them, so commands that restructure a table dispatch with `filter: false`. The cursor must never sit inside a replaced range (typed text lands at the end of it): padding up to the cursor counts as cell text. A mark only wraps a replace decoration that ends where it ends if it is `inclusiveEnd`. The cursor is drawn next to what it sticks to (`assoc`; 0 counts as "what follows"), so every cell mark ends with its closing pipe (something of the same cell follows the end of its text, also in `|a|b|`) and `stayInCells` makes cursors at the start of a cell stick forward; otherwise the caret shows up in the neighbouring cell. A table is shown as markdown while the cursor is on its delimiter row, and never when it is inside a quote/list or has a row without a leading pipe. lezer-markdown: a table can't interrupt a paragraph, and any line right below a table is a row of it (so the editor puts an empty line in front of text typed there).
- Markdown editor math (`editor/math.ts` = lezer-markdown extension, `Formula` widget in `preview.ts`, `typstMath()` in `src/lib/typst.ts`): `$…$` must hug its content, end in its line and not be followed by a digit (prices); a line starting with `$$` opens a block up to a line ending with `$$` (like a fence, so an unclosed one swallows the rest of the note: the second `$` typed at a line start gets its closing pair). A formula of several lines is drawn in its first line and the others get `display: none`. Typst sizes an inline formula like a line of text and lets fractions/indices reach out of it, so the SVG is inlined with `overflow: visible` (not an `<img>`), and put on the baseline with `vertical-align` from a measurement in Typst. `typst.query()` of typst.ts 0.7 doesn't compile first: `query()` in `typst.ts` goes through `runWithWorld`. SVG sizes are rounded up to whole pt.
- Markdown editor code and images (`preview.ts`): `syntaxTree().iterate` also walks the trees of the languages inside code blocks and HTML, whose node names collide with markdown's (JS has `Escape`), so `FencedCode`/`CodeBlock`/`HTMLBlock` return `false` from `enter`. Tailwind's preflight makes `img` a block: widgets set `display` themselves. The image widget stays one DOM node while the cursor moves in and out (`updateDOM`), otherwise it reloads and the text jumps. Picture options live in the alt text (`![alt|center|300x200](src)`, `editor/images.ts`: `imageOptions()`, `setImage()`); a click on a picture shows it large (`zoom()`, the plugin swallows the `mousedown` so the cursor stays), its markdown is reached with the keyboard or the menu's "Edit markdown".
- Markdown editor folding and popups (`editor/index.ts`, `preview.ts`): CodeMirror's `foldGutter`; a `foldNodeProp` override in the markdown config leaves only list items foldable besides heading sections (lang-markdown's fold service), since the blocks we draw ourselves don't mix with folds. The gutter's 1rem is taken out of the scroller's left padding. Folds are not stored. The inline-formula popup is a `showTooltip` state field whose tooltips all share one `create` function (CodeMirror keeps a tooltip only then, instead of rebuilding it per keystroke). Code block lines inside a list paint their box with layered gradients (`indented()` in `theme.ts`), since `border-radius` can't round a box that starts at the list indent.
- ical.js: `new ICAL.Time(data, zone)` ignores `zone` when `data` has a `timezone` key (`toJSON()` has one); a `TZID` without its VTIMEZONE in the file parses as floating. `ICAL.Recur` keeps the order of an RRULE's parts, so the preset strings in `RECURRENCE_PRESETS` survive a round trip.
- `tests/dav.test.ts` runs against a small CalDAV server inside the test; `CALDAV_TEST_URL=http://127.0.0.1:<port>/<user>/` runs it against a real one (`nix shell nixpkgs#radicale -c radicale --storage-filesystem-folder=<dir> --auth-type=none --server-hosts 127.0.0.1:<port>`, `MKCOL` the user folder first).
- `tests/mail.test.ts` runs its IMAP part only with `MAIL_TEST_IMAP=127.0.0.1:<port>` (implicit TLS, `MAIL_TEST_USER`/`MAIL_TEST_PASS`, default a fresh user + `secret`): a scratch Dovecot from `nix shell nixpkgs#dovecot` started as the normal user with a static passdb (`password=secret`), static userdb (`uid`/`gid` = you, maildir under the scratch dir), `Sent`/`Archive` with `special_use`, a self-signed cert, `chroot =` for imap-login and anvil, and a **short `base_dir`** (e.g. `/tmp/dv.XXXX`: unix socket paths under the session scratchpad are too long). The test sets `MAIL_TLS_INSECURE=true`. `scripts/mail-spike.ts` exercises IMAP + SMTP (Mailpit as sink) the same way.
- Browser testing: no Chrome extension. Use headless `nix shell nixpkgs#chromium` + `playwright-core` (script in the session scratchpad; see "Verification").
- The user often has their own dev server running on the real `data/` (seen on port 5199, bound to `[::1]`). For test runs pick another port with `--strictPort`, address it as `127.0.0.1` (not `localhost`, which may resolve to the user's server), and check that the notes list is the scratch one before writing anything.

## Migrations (required)

Whenever a change affects stored data or deployment (doc shapes in `types.ts`, scene/customData formats, file layout in `DATA_DIR`, env vars, Docker/compose setup), write a migration guide so existing instances and files keep working with the new version:

- Add an entry to `MIGRATIONS.md` (newest first): date, what changed, whether old data still works as-is, and the exact steps (or script) to upgrade.
- Prefer backwards-compatible changes (new fields optional, old shapes still read). If old data needs converting, ship an idempotent migration (e.g. a script in `scripts/` or a check on startup) and reference it in the guide.
- Mention breaking changes in the final summary to the user.
